## 1. 验收目标与判定原则

验证：插件显式停用／卸载生效后，自有会话进入原生未分组，任务目录及历史原位保留；重新启用后只接回仍符合条件的旧会话。普通重启保持登记身份；用户停用期间的收编等操作优先。

所有测试以设计 R01–R18 为依据。旧测试若要求启动删除已归档空目录，应更新为保留；不能为旧断言通过而维持旧 GC。反过来，也不能简单删除失败测试并宣称无回归。

结果分类：

- `PASS`：前置条件、执行、断言和证据完整，并符合预期，包括预期发生且没有数据损伤的冲突。
- `FAIL`：实现结果违反断言或出现未解释的数据变化。
- `BLOCKED`：宿主／环境缺能力，测试未到达有效断言；不是 PASS。
- `NOT_RUN`：未执行。
- `N/A`：仅限文中明确条件项，有实际环境证据和替代覆盖说明；核心停用、卸载、恢复、文件保留与旧会话继续工作不可 N/A。

完整结论为 COMPLETE，必须所有核心用例 PASS。若默认测试跳过原生契约，或只跑 jsdom，结论至多 PARTIAL。记录测试数量时分别列 PASS/FAIL/BLOCKED/NOT_RUN/N/A，不把 skip 合并进通过数。

## 2. 执行范围和数据约束

只在本任务专用的隔离 DSH 数据根、profile、端口和浏览器测试实例执行生命周期变更；生产 profile、真实会话和正在使用的 GUI 仅可做只读定位，不得执行停用、卸载、交接或大批恢复。

- 通过原生插件管理器／服务操作工作区；不手写 Workspace 存储 JSON、Session 日志或生产 profile 配置制造结果。
- 为测试安装依赖或候选包，只操作隔离环境；不在真实 profile 下运行包管理器。
- 验收不通过手改待测源码纠正状态。发现 bug 回到开发阶段修复、重新提交／打候选包，再执行受影响用例。
- 新测试 Session 保留并最终归档，不删除 Session 记录或 `session-*` 目录。工作区登记的删除是被测功能，并非删除 Session。
- 目录缺失／移动／替换等负向条件只对新建的专用合成夹具操作；可把夹具目录改名到测试保留区模拟缺失，禁止迁移真实用户目录；结束后记录实际位置，不清除证据。
- 不调用现有批量 `/chat-sessions/unarchive`；归档／恢复使用单个夹具的原生操作。links/tidy 只做只读／dry-run 观察。
- 浏览器工具遵守当前会话技能与持久 profile 约束；同一工具要求 default space 时复用它，任务结束不关闭用户持久浏览器。测试身份与数据仍须隔离。

开始前写明允许变更的绝对路径列表；每次删除登记都记录目标 Workspace ID 和夹具 room；任何磁盘 move/delete 前核实目标绝对路径属于合成夹具。

## 6. 快照与独立验收判据

所有变更用例按统一模板执行：`B0 基线 → 原生触发 → B1 生效后 → 原生刷新／重启（若适用）→ B2 → 启用 → B3 → 最终复核`。步骤边界使用服务／DOM 可观察条件或可控 barrier；不以固定 sleep 到时当完成。

每个快照至少含：

1. 原生 Workspace 的 ID、canonical path、成员 ID 全集；所有 Session 的 ID、持久 header cwd、origin、原生归档和 pin 顺序。
2. 原生 Session 全集与所有 Workspace 认领集合差集：`ungrouped = sessions − union(workspace.sessionIds)`。同时报告 blank／archived／search 的显示过滤，不能凭侧栏没看到认定数据丢失。
3. 任务文件清单：相对路径、lstat 类型、大小、SHA256；空目录也列出；symlink 用 readlink 目标，不跟随未知链接；支持时记录目录 dev/ino 和 mode。
4. 标题软链接与 `.archive` 的链接名称／目标、`.links.json` 字节哈希；元数据账本不计入任务文件树。
5. Session 日志长度／哈希／header。交接期间无聊天动作的静止用例应逐字节相同；若宿主自身有原生追加，必须验证旧内容完整前缀及追加事件来源，未知变化 FAIL。
6. 新账本 revision、scope、room/member 状态、operationId、generation、lock 状态；快照只读。
7. 当前 GUI URL、截图或视频时间码、原生菜单操作、浏览器控制台和宿主错误。

用原生查询和独立文件快照作为验收 oracle，不能仅断言“插件 status 说 completed”。插件退出后接口消失是预期，但账本与原生快照仍能检查。

B0→B1→B3 的文件比较必须遍历整个夹具树和所有标题入口，不能只检查一个 sentinel 文件。为工具继续工作安排的显式写入，仅允许预先声明的输出文件；其余路径仍须一致。

## 12. 执行顺序与命令约定

建议按以下阶段推进；每阶段发现缺陷后修复并重跑受影响依赖，不反复全量跑无关测试。

1. 检查新分支和隔离环境，采集宿主版本，完成 G0。
2. 执行 L1 状态机／账本／创建意图／迁移／故障注入；明确每个 failure branch 的期望。
3. 执行 L2 原生契约，建立所有标准夹具及 B0。
4. 从候选 tgz 执行 L3 核心生命周期、用户介入和继续工作。
5. 受控并发与真实崩溃恢复，随后回归／规模／包体核对。
6. 生成最终 traceability、报告与复验命令；保留测试 Session，按约定归档，停止仅本任务启动的隔离实例。

当前仓库已有：

```sh
npm run check
npm test
npm run test:native
npm pack --dry-run --json
```

`test:native` 当前依赖本机宿主及 `DSH_NATIVE_WORKSPACE_CLIENT`；缺少依赖可能 skip，执行者必须检查测试输出而非只看退出码。

本次开发应新增并真实实现以下命令（目前基线尚无这些脚本）：

```sh
npm run test:lifecycle
npm run test:lifecycle:native
npm run test:lifecycle:e2e
```

前者包括状态机／存储／故障测试并纳入默认 npm test；后两者必须连接本次隔离实例、核验隔离路径和候选构建，支持输出证据目录。若工程选择等价脚本名，三份执行文档及最终报告必须同步，提供完整可复验命令，不留未实现的脚本占位符。

生成 tgz 使用 `npm pack --pack-destination <已核实的仓库外artifact目录> --json`，记录退出码、输出文件和 SHA256。命令里的 artifact 目录由执行者创建和核实，不能把占位符原样执行。生产 profile 不作为打包目录。


自动化断言失败时保留失败那次证据，后续重跑通过不能覆盖原件。超时先记录当时 native／UI／账本状态再判定，不无限 retry 到一次成功。
