# 配置参考

[返回 README](../README.md) · [English](CONFIGURATION.en.md)

以下为 v0.2.0 实现读取的全部插件配置：6 个常用项、2 个实验选项，以及已停用的 `idleMs`。未填写时采用默认值。

## 设置方式

通过 DSH 支持的插件配置方式，设置 `chat-sessions` 插件行的 `config`。下面仅展示 `config` 的内容，无需为每项显式填写默认值：

```yaml
root: ''
flattenUngrouped: true
glide: true
glideMotion: auto
treeBadge: icon
untitledWorkspaceTitle: 独立对话
ownership: workspace
seedFirstTurn: false
```

保存后按宿主提示重新加载插件或重启 DSH；前端配置在插件客户端加载时读取。

## 常用项

| 配置项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `root` | 字符串 | `''` | 房间存放位置。留空时使用 `$DSH_HOME/chats`，未设置 `DSH_HOME` 时用 `~/.dsh/chats`。自定义时填写绝对路径；不展开 `~` 或环境变量，更改此项不会迁移旧数据。 |
| `flattenUngrouped` | 布尔值 | `true` | 启用独立对话侧栏分组，展平插件管理的工作区。设为 `false` 时保留原生工作区分组，不启用插件的侧栏分组整理；后台工作区与目录维护仍运行。 |
| `glide` | 布尔值 | `true` | 插件侧栏滑行动效的总开关。设为 `false` 时关闭插件滑行，即使 `glideMotion` 为 `force` 也不播放。 |
| `glideMotion` | `auto` / `off` / `force` | `auto` | `auto` 遵循系统或浏览器的减少动态效果偏好；`off` 关闭插件滑行；`force` 忽略该偏好并允许滑行，仍受 `glide` 控制。 |
| `treeBadge` | `icon` / `tint` / `off` | `icon` | 树形视图中，独立对话嵌套在其他工作区下时的视觉标记。`icon` 添加对话图标；`tint` 降低会话行不透明度，悬停时恢复；`off` 关闭该标记。 |
| `untitledWorkspaceTitle` | 非空字符串 | `独立对话` | 插件创建的底层工作区及输入区工作区标签的名称。名称保持独立于会话标题；维护会将已有受管工作区的名称同步为此值。空字符串或非字符串使用默认值。 |

`glide` 和 `glideMotion` 只控制插件添加的滑行，不接管 DSH 自带的全部动画。`flattenUngrouped: false` 时，侧栏分组整理及其滑行、树形标记不启用。

## 实验选项

这两项用于实现验证，日常使用请保持默认值。

| 配置项 | 类型 / 可选值 | 默认值 | 行为与限制 |
| --- | --- | --- | --- |
| `ownership` | `workspace` / `bare` | `workspace` | `workspace` 为新房间注册原生工作区，支持原生输入区。`bare` 创建没有工作区归属的会话；当前宿主依赖工作区来开放输入区，此模式不适合日常对话。切换此项不构成已有数据的迁移或退出管理操作。 |
| `seedFirstTurn` | 布尔值 | `false` | 仅在显式设为 `true` 时，为新建会话写入一个空的首轮，不作用于复用的空白会话。已知会与原生首轮编号冲突，后续读取可能报 `SessionFormatError: turn/start does not open the expected turn`，请保持关闭。 |

## 生命周期与账本

停用、卸载、重新启用时的会话交接由插件自动完成，没有配置项。相关行为与位置：

- **账本位置**：`<DSH_HOME>/storages/dsh-chat-sessions-lifecycle/<scopeId>/ledger.json`（同目录下还有 `lock.json`）。它位于安装包和房间目录之外，只记录会话 ID、路径、阶段与错误码，不记录对话内容。
- **scope 身份**：由「DSH 数据根 + 当前 profile 名 + 插件标识 + 规范化后的 `root`」共同决定。换 profile、换 `DSH_HOME`、换 `root` 都会得到新的 scope，不会隐式迁移旧记录（切换后旧 scope 的账本原样保留）。
- **单 writer 锁**：同一 scope 同时只允许一个插件实例写入；拿不到锁时插件进入只读降级并报 `LOCK_HELD`，不会并发改原生登记。
- **降级状态**：账本损坏、schema 版本更高、锁冲突或关键恢复写入失败时，插件关闭生命周期写入口并报告 `DEGRADED`。账本无效时托管集合为空；其他降级原因按账本中可确认的成员返回集合，不据此开放自动写入。
- **中断恢复注意事项**：强制结束进程恰好发生在原生 Workspace/Session 创建与账本收尾之间时，可能留下未托管的原生工作区。查看状态诊断；若诊断提供工作区 ID，在 DSH 工作区列表核对该 ID 的路径与成员。若无 ID，从 DSH 工作区列表检查位于本插件 `.sessions` 下的空工作区。确认该登记为空后，可在 DSH 中删除该工作区登记；若已有成员或路径不明确，保留工作区并手动重新分配会话。不要删除 `session-*` 目录或会话日志，也不要手改 `workspace.json`/生命周期账本。该边界不做自动猜测清理。
- **本地写入检查**：指定旧工作区补接管前会验证 ID 仍存在；请求不存在的 ID 返回 HTTP 400，不更改账本。
- **历史格式**：损坏或不完整的 history 记录不会作为恢复源；目前未对每一条坏记录单独生成诊断。若状态显示 history 恢复被阻塞或账本内容异常，停止插件生命周期操作并保留账本、history 和锁文件供检查。不要在持有者仍运行时手动移动/重命名锁文件，也不要直接覆盖或删除账本/history。
- **目录**：本版起不再回收任何房间目录（含已归档空目录）。删目录请在文件系统里自己做。

`/chat-sessions/status` 还额外返回 `managedWorkspaceIds` 与 `managedSessionIds`：前端据此判断哪些工作区属于插件，停止按路径形状推断归属。

## 已停用项

| 配置项 | 状态 | 说明 |
| --- | --- | --- |
| `idleMs` | v0.1.1 起忽略 | 旧版按日志闲置时间自动归档的阈值。保留旧配置不会生效，也不会启用启动归档。 |

v0.1.1 中，空白会话由用户手动归档；插件启动或重新启用时保留未归档会话，启动维护会回收**已经归档**、没有未归档会话共享的自有空目录（允许仅有 `.DS_Store`），并保留会话日志与归档状态。从 v0.2.0 起，插件不再自动回收任何房间目录（包括已归档的空目录），停用或卸载插件也不会自动归档会话。

除上表外，目前没有闲置归档、启动自动归档、轮询间隔或空目录回收开关等插件配置项。`DSH_HOME` 是宿主环境变量，影响默认 `root`，不属于插件行的配置字段。
